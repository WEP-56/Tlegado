# 发现书源适配

更新日期：2026-09-30。

## 本次定位

对默认本机数据库进行只读检查时，共有 81 个书源，其中 57 个开启发现并配置发现入口：28 个静态 JSON、15 个文本分类、14 个动态 JS。静态 JSON 中 26 个使用已有的尖括号对象兼容格式；标准化后 28 个均可解析，其中 13 个首项是空 URL 的分组标题。5 个动态分类脚本使用 org.jsoup.Jsoup 读取 HTML。

原逻辑在启动/导入快照时执行所有分类脚本，错误被 unwrap_or_default 转为空分类；列表再根据分类是否为空决定显示，导致失败书源直接消失。空 URL 分组标题又被当作默认分类，用户进入后不能得到书籍。以上数量只说明本地配置分布，不是联网可用率。

## 已调整

- 按发现开关和发现入口显示书源，与搜索开关独立。分类尚未加载或解析失败不会隐藏书源；界面统一称为“发现”。
- 启动、导入及开关刷新只加载元数据，选择书源后才在后台执行分类规则。分类失败显示错误及重试入口；切换、取消、重新导入后丢弃过期结果，并限制后台任务并发。
- 空 URL 项按分组/说明处理，不作为可请求的标签；自动选择第一项有效链接。若只有说明，显示书源给出的“请先登录”等内容。当前终端标签仅展示有效分类，不复刻 Android 的分组样式或表单控件。
- r 重试分类错误或失败书籍页；R 重新执行分类规则；h/l 切换分类；n 加载下一页；Backspace 返回发现书源列表。
- 分类 JS 标记不区分大小写，支持直接返回数组或返回 JSON 字符串；损坏的 JSON 不再伪装成单个分类。
- 增加常用只读 Jsoup 接口：org.jsoup.Jsoup.parse / Packages.org.jsoup.Jsoup.parse、select/selectFirst、集合索引/get/size/first/last、text/attr/html/outerHtml 等。底层使用现有 scraper CSS 引擎；不支持的选择器明确报错。
- 发现列表为空时，按 Legado 行为尝试详情页规则。HTTP 非成功状态和首页无法解析到书籍显示错误；后续页为空仍视为正常结束，保留重试和分页逻辑。

## 验证

本地 HTTP 夹具覆盖动态 Jsoup 分类、分类规则到分页请求的链路、HTTP 403、首页空解析及末页为空。TUI 回归覆盖未解析书源可见、搜索关闭但发现开启、分组标题不请求、分类失败重试、取消后的旧结果丢弃，以及快照不执行分类脚本。

完整回归：设置 CARGO_INCREMENTAL=0 后执行 cargo test --workspace --locked --offline -j 4，236 项通过、0 项失败、1 项真实站点联网测试跳过（核心及集成测试 158 项，TUI 78 项）。本次新增 9 项；原有发现分页及 3000 书源导航回归继续通过。日志见 [discovery-tests.log](audits/discovery-tests.log)。

本轮关闭增量编译是为绕过本机 Rust 增量缓存读取崩溃；不是跳过测试。修改文件的 rustfmt、Jsoup JS 语法及 git diff --check 均通过。测试仅使用本地 HTTP，不宣称全部真实书源联网成功。

## 边界

登录表单、发现 type/action 控件、exploreScreen、WebView 与完整 Java/Rhino API 尚未实现。需登录或反爬的站点仍可能失败，但分类错误不再令书源从列表中消失。Jsoup 仅覆盖常用只读 API，不包含完整 DOM 修改、Java 包导入及全部 Jsoup 特有伪类。

取消会立即忽略对应结果，并阻止尚未获得执行许可的旧任务；已经开始的同步脚本/HTTP 不会强制中断。
