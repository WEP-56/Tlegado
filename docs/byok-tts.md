# BYOK 网络听书

网络听书复用已确认的 `p`、暂停/继续、切段、切章、倍速、定时和高亮交互。默认仍使用系统语音；选择 HTTP 后端后，按 `p` 才开始发送正文到所配置的服务。可在 TUI 的“设置 → 听书设置”中配置当前后端，也可使用配置文件。

## 已验证的服务商情况

项目内的四平台实测记录显示，严格遵循 OpenAI 兼容语音接口的服务（例如 tts.ai）可以直接使用默认配置。其它平台需要先对照其实际协议填写自定义字段：

| 情况 | 配置方式与判断 |
| --- | --- |
| 标准兼容接口 | `endpoint` 指向完整的 `/audio/speech` 类 POST 地址，填写 `model`、`voice`，使用默认请求体。 |
| voice 已编码在 URL 的接口（例如 ElevenLabs 风格） | 把完整 voice URL 填入 `endpoint`；使用 `header_env` 配置 `xi-api-key` 等认证头；填写自定义 `body_template`，其中只保留服务商要求的文本字段。自定义请求体下 `model`、`voice` 可留空。 |
| 返回 402 | 通常表示账户、额度或服务商侧策略问题，应先在服务商控制台确认，不能由客户端重试解决。 |
| 只有 `/v1` 根路径或非标准路径 | 需要查服务商文档中的实际语音合成 POST 路径，并按其字段配置；程序不会自动拼接路径或猜测协议。 |

测试记录中的访问密钥仅用于临时验证，文档和示例不会复制它们。若密钥曾进入共享日志或版本库，应在服务商控制台撤销并重新生成。

## 快速开始

### 在 TUI 中配置

1. 启动程序，在侧栏“设置”下选择“听书设置”，按 Enter 进入。
2. 在“听书后端”按 Enter 切换到 HTTP 网络语音。
3. 用 ↑/↓ 选择接口地址、模型、声音、API 密钥，按 Enter 编辑；支持终端粘贴。无需先创建配置文件或设置环境变量。
4. 对 MiMo 将“响应模式”切换为 `json_base64`；普通 `/audio/speech` 服务保持 `audio`。再把“请求体”粘贴为 MiMo 示例中的 JSON。
5. 按 **Ctrl+S 保存并立即生效**，返回阅读后按 `p` 启动。保存本身不会调用服务商或发送正文。

编辑时 Enter 确认当前字段，Esc 取消当前字段，Tab/Shift+Tab 确认并选择下一项/上一项，Ctrl+U 清空。光标支持左右、Home/End、Backspace/Delete；输入 `q`、`/`、`?` 等不会触发页面导航。列表状态下 Esc 返回侧栏，未保存草稿暂时保留；`R` 撤销到上次保存的配置。草稿不会改变实际听书后端，退出程序不会保存草稿。

系统后端可填写系统声音名称；留空沿用 `TLEGADO_TTS_VOICE` 或自动选择。HTTP 后端还可编辑格式、超时、重试、缓存、预取、请求头和自定义请求体。切回系统后端时保留 HTTP 配置，重新启动后也可切回继续使用。

**密钥输入及展示始终遮罩，但直接填写的 API 密钥会明文存入页面显示的本地配置文件。** 不希望密钥落盘时，清空“API 密钥”，填写“密钥环境变量”；两项不能同时填写。自定义鉴权请求头仍通过“请求头 → 环境变量”配置。不要分享含密钥的配置文件。

保存位置遵循下述配置查找优先级，使用 `--tts-config` 时会写回该文件。保存使用临时文件原子替换；校验或写入失败会显示错误，保留草稿，不应用失败的配置。演示模式未指定数据目录或配置文件时，仅在本次运行生效，不写入磁盘。

### 使用配置文件

1. 将 [兼容接口示例](examples/tts-http.example.json) 复制为自己的 `tts.json`。
2. 填写服务商提供的完整语音合成 `endpoint`、`model`、`voice`。程序不会自动补齐接口路径；示例域名和模型名称均为占位符。
3. 将密钥放进配置所指定的环境变量，然后启动：

```powershell
$env:TLEGADO_TTS_API_KEY = "你的服务商密钥"
cargo run -- --tts-config "E:\Reader Config\tts.json"
```

也可将配置保存为数据目录下的 `tts.json`，之后直接运行 `cargo run`。配置查找顺序为：`--tts-config`、`TLEGADO_TTS_CONFIG`、数据目录 `tts.json`；均未指定时使用系统 TTS。配置在启动时加载；外部编辑文件需要重启，TUI 内保存立即生效。切回系统语音可使用 `{"backend":"system"}`，指定系统声音可加 `"voice":"声音名称"`。TUI 切回系统时会用可选的 `http` 字段保留未启用的 HTTP 参数。

`--demo --tts-config ...` 也可验证网络听书。演示模式未指定数据目录时不读写磁盘语音缓存；它仍会向配置的服务发送演示正文并可能产生服务商费用。

## 请求配置

| 字段 | 含义 |
| --- | --- |
| `backend` | `system` 或 `http` |
| `endpoint` | 完整 HTTP(S) POST 地址，可用于自托管服务；不跟随重定向 |
| `api_key_env` | 环境变量名；读取其值并生成 `Authorization: Bearer ...`。无需鉴权的本地服务可省略 |
| `api_key` | 可选的直接密钥，生成 Bearer 请求头；明文保存在本地，与 `api_key_env` 二选一 |
| `model` / `voice` | 服务商支持的模型和声音名称；默认兼容请求必须填写 |
| `response_format` | `wav`（默认）、`mp3`、`flac`、`ogg` |
| `response_mode` | `audio`（默认，接口直接返回音频字节）或 `json_base64`（从 JSON 音频字段解码 Base64） |
| `headers` | 非敏感静态请求头；不能用它保存 Authorization、api-key、Cookie 等认证值 |
| `header_env` | 请求头名称到环境变量名称的映射，用于 `x-api-key` 等鉴权；变量值原样发送 |
| `body_template` | 可选 JSON 对象，用于自定义字段名和嵌套结构 |
| `timeout_seconds` | 单次请求与下载总超时，1–120 秒，默认 45 秒 |
| `retries` | HTTP 429/5xx 的额外重试次数，0–2，默认 1；不自动重试鉴权失败、格式错误或网络超时 |
| `cache_max_mb` | 本地缓存预算，0–1024 MiB，默认 256；0 关闭磁盘缓存 |
| `prefetch` | 默认 `false`；启用后最多预取下一个合成片段，见下文 |

MiMo-V2.5-TTS 使用 Chat Completions 形式，返回 JSON 中的 Base64 音频，不能使用默认 `/audio/speech` 请求。可直接复制 [MiMo 配置示例](examples/tts-mimo-v2.5.json)，设置 `MIMO_API_KEY` 后运行。示例使用官方字段：`messages[0]` 提供语气说明，`messages[1]` 的 assistant 内容为正文，`audio.format` 为 `wav`，`audio.voice` 为 `mimo_default`。

默认兼容请求为：

```json
{
  "model": "配置中的模型",
  "voice": "配置中的声音",
  "input": "当前合成片段的净化正文",
  "response_format": "wav",
  "speed": 1.25
}
```

非标准接口可参考 [自定义请求示例](examples/tts-custom.example.json)。模板支持 `{{text}}`、`{{model}}`、`{{voice}}`、`{{format}}`、`{{speed}}`，仅替换 JSON **值**。独立的 `"{{speed}}"` 会变成数字；嵌入字符串时保持字符串。正文中的引号、换行按 JSON 编码，正文中类似占位符的内容不会被再次解释。不执行 JavaScript 或 shell。

环境变量模式下只填写变量名，直接密钥模式使用 `api_key` 字段。原始响应正文、请求 URL 和密钥不会拼入网络错误提示。HTTP 错误显示状态码，服务商详细错误请在其控制台检查。配置引用的密钥环境变量缺失时会在发起请求前报错，不会自动回退为另一家服务。

## 播放、调速与取消

- 每个合成片段完整下载并通过音频校验后才播放；片段仍按原文段落高亮，长段落不改变上一段/下一段的含义。
- 下载中显示“准备中”。暂停会保留当前下载，但下载完成后不会自行发声；继续时播放已下载内容。
- 停止、跳段、切章和退出会停止播放器并取消不再需要的下载。取消本地请求不代表服务商一定停止已经开始的合成或计费。
- 倍速传给服务端 `speed`，从**下一个合成片段**生效，不对当前音频做改变音高的播放端变速。自定义模板需要将 `{{speed}}` 放到服务端支持的字段中才有调速效果。
- 网络失败、错误内容、损坏音频或设备错误会暂停并显示错误，`p` 重试当前片段，`s` 停止。

## 缓存和预取

缓存位于数据目录的 `tts-cache/`。文件名使用请求地址、实际请求体、非敏感请求头和环境变量名称的 SHA-256；正文、声音、模型或语速变化不会误用其他请求的音频。密钥值不参与缓存键。

只缓存通过解码校验的音频；损坏缓存会重新下载。达到预算后按写入时间淘汰旧缓存，仅处理该目录中符合哈希命名约定的 `.audio` 文件。写入失败不影响播放。程序停止后可删除该缓存目录来释放空间。

`prefetch: true` 时，播放当前片段期间预取长段落的下一个片段，或当前章节下一段的首个片段。不会预取下一章。匹配的结果跨段复用，不提前播放；跳到其他内容时取消不用的预取。预取可能合成后来没有听到的内容，需自行考虑服务商计费，因此默认关闭。

## 当前边界与验证

支持返回 WAV/MP3/FLAC/Ogg 音频字节的 JSON POST 服务，不支持返回 JSON/base64、音频 URL、SSE、裸 PCM 或需要异步轮询任务的接口。单个响应限制为 32 MiB。HTTP 分块传输可以接收，但当前不做边下载边播放。

已用本地 HTTP 模拟服务验证请求模板、凭据头、重试、错误内容、下载取消、暂停、缓存和预取，并在 Windows 完成“HTTP 下载 → 解码 → 真实设备播放”的短音频测试。尚未使用真实付费服务商密钥验证具体模型；macOS/Linux 设备播放也需要对应平台实测。

Linux 源码构建新增 ALSA 开发依赖，Debian/Ubuntu 可安装 `libasound2-dev` 和 `pkg-config`；发布构建工作流已加入这一安装步骤。运行网络听书需要可用的默认音频输出设备。
