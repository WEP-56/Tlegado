# Legado 首个阅读闭环验收

日期：2026-09-28。环境：Windows / PowerShell，Rust 1.95.0。

## 已实现

- 正式 Cargo workspace 引入 `crates/legado-core`；保留 MIT 来源及 PDF vendor 许可，不依赖被忽略的参考目录。
- 默认真实模式，`--demo` 保留原演示；后台任务调用领域服务，页面不直接执行网络和数据库操作。
- 书源单对象/数组/BOM/旧版 JSON 导入，整批事务保存，JSON 导出、启停和探索开关。
- 多源搜索和分类发现第一页，详情、目录、正文、缓存及书架/历史/进度持久化。
- 读取结果按任务编号过滤；取消停止后续调度，已发出的请求正常结束。切章失败保留当前正文。
- 保存串行执行；退出前排空已提交的保存命令，未恢复的进度写入失败会作为退出错误报告。

## 可执行文件验证

已通过实际二进制检查 `--help`、含中文和空格路径的 UTF-8 BOM JSON 导入、非法批次退出码、缺少导入路径时的退出码，并直接查询 SQLite 确认非法批次未改变已有书源。

Windows PTY 中启动真实模式，键盘进入书源管理，打开导入弹层并输入测试文件路径；导入成功后切换启停，直接查询 SQLite 确认 `enabled=false`。随后正常退出，进程返回 0，观察到离开备用屏幕、关闭鼠标捕获和恢复光标的终端序列。

构建环境曾提示 E: 盘无法硬链接增量缓存，编译器自动改用复制；此项属于本机缓存性能提示。

## 后续修复：搜索/探索日志扰乱终端

用户实测发现网络请求日志直接写入 TUI。根因是 fetcher 的三处 `println!`，普通测试的输出捕获此前隐藏了问题。现改为由宿主控制输出的 `tracing::debug!`，不记录请求 URL 或正文。新增子进程测试以 `--nocapture` 执行 GET、带正文 POST、500 响应及重试，检查 stdout/stderr；该回归及原搜索/发现/阅读/离线缓存端到端测试均通过。


## 后续修复：千源导航、批量管理和后台 panic

2026-09-28：侧栏将逐源发现入口收拢为“探索书源”目录及至多一个当前探索书源。新增名称/分组/URL 筛选、状态筛选、分页/首尾定位、多选、全选筛选结果、统一启停、探索开关与确认删除。批量保存和删除使用 SQLite 事务；游标与多选按书源 URL 保持，删除不触碰书架和缓存。

截图中的第二类终端破坏来自 JavaScript 的阻塞 reqwest 客户端：在 Tokio 异步上下文第一次构造时 panic，原全局 panic hook 又从后台线程执行了终端恢复。现将 java.ajax、java.get 与远程 jsLib HTTP 完整生命周期放在普通线程，多线程 Tokio 在等待时释放工作线程；请求超时 15 秒。后台 panic 写入数据目录 panic.log，由任务错误事件回传 UI；主线程 panic 仍恢复终端并报告错误。

验证结果：workspace 共 160 项测试通过，1 项外网测试默认忽略；根包格式检查、Clippy（-D warnings）、git diff --check 和 debug 构建通过。新增回归覆盖 3,000 源的固定侧栏规模与多尺寸绘制、筛选多选/删除确认、刷新后的 URL 定位、批量状态重启持久化、删除失败整批回滚及命名空间隔离。两个子进程回归分别验证 JavaScript HTTP 首次初始化/重复调用/远程库加载（单线程和多线程运行时），以及捕获后台 panic 后没有终端输出或恢复控制序列。

真实 Windows PTY 使用隔离临时数据目录导入 1,200 个测试书源，按分组筛选并禁用其中 600 个，直接查询 SQLite 确认仅目标组变更。再导入 1 个本地 JavaScript 测试源，搜索经 java.ajax 获取搜索 URL 后返回 1 条书籍、0 个失败，进程继续接受操作且 panic.log 为空。删除弹框取消后 1,201 个源均保留；确认删除筛选的 600 个后剩余 601 个，其余组保持不变。正常退出码为 0，退出时恢复备用屏幕、鼠标与光标。未读写用户实际数据目录。
